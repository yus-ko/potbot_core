# APF（人工ポテンシャル場）の既知問題点と現状の回避策

## 概要

APF（Artificial Potential Field）法は引力・斥力ポテンシャルを組み合わせた経路計画手法だが、
いくつかの構造的な問題を抱えている。本ドキュメントでは M9 の実装・検証を通じて確認された
問題点と、それぞれの回避策・残課題をまとめる。

---

## 問題1: 局所解（Local Minima）

### 現象

ロボットがゴール以外の地点でポテンシャルの局所最小点に捕まり、勾配降下法が進行できなくなる。

典型的な状況:
- 引力（ゴール方向）と斥力（壁方向）が釣り合う地点
- 壁の手前でゴール方向へ進めなくなる

### 回避策: weighted escape 機構（M9 T-003で実装）

局所解を検出したら、100回のランダム試行で近傍セルの中から最小 J 値（重み付きスコア）を持つセルへジャンプする。

```
J = wu * PotentialValue / (PotentialValue + posediff)
  + w_theta * posediff / (PotentialValue + posediff)
```

**修正前の問題（T-003 バグA）**: `break_flag` により1回目の試行で即終了し、
ランダム重みと探索範囲の拡大（range 1→最大11）が機能していなかった。

**修正後**: 全100回を必ず実行し、グローバル最小 J 値を持つセル `best_idx` を追跡する。

```cpp
size_t best_idx = SIZE_MAX;
for (size_t i = 0; i < 100; i++) {
    // ...範囲内の全セルを評価...
    if (J < J_min) { J_min = J; best_idx = idx; }
    // 次の反復のためにランダム化
    wu = random; w_theta = 1-wu;
    random_range = random * 10 + 1;  // 最大 11 セル = 0.55m
}
```

### 残課題

探索範囲が 11 セル（0.55m）に制限されるため、深い局所解では脱出に複数回の
脱出→勾配降下サイクルが必要になる場合がある。

## 問題2: 狭い開口部問題（Narrow Passage Problem）

### 現象

壁の開口部（ドア・廊下など）を通過できない。APF の Euclidean 引力では
開口部中心でも**ポテンシャルが局所最大**になるため、勾配降下法が開口部を回避してしまう。

**なぜ開口部が局所最大になるか**:

```
壁セル[IS_OBSTACLE] ─── 開口部 ─── 壁セル[IS_OBSTACLE]
         ↑斥力大            ↑              ↑斥力大
                      隣接壁セルからの
                      斥力が合算される
                      → ポテンシャル高！
```

開口部中心でも隣接する壁セルすべてからの斥力が加算されるため、
開口部はポテンシャルの「山」になる。勾配降下法はこの山を回避して
開口部を通れない。

これは **Euclidean 引力 + 斥力合算** という APF の構造的問題であり、
Dijkstra 法（BFS 波面伝播）では発生しない。

### 回避策: LOSチェックなし + Nav2 回復動作

M9 T-003 の検証を通じて、以下の回避策に落ち着いた:

1. **脱出ループで LOS チェックを行わない**
   開口部の向こう側（goal-side）セルも候補に含めることで、脱出が壁を越えて
   ゴール側のセルへランダムジャンプできるようにする。

2. **IS_OBSTACLE セルは明示的にスキップ**
   壁セル自体への経路点配置は防止する。

3. **Nav2 の回復動作（spin / wait / backup）に委ねる**
   脱出がゴール側セルへジャンプした場合、生成経路には「壁を越えるセグメント」が含まれる。
   コントローラー（OptimalPathFollower）がそのセグメントを追従しようとすると
   `Failed to make progress` が発生するが、Nav2 の回復動作が介入して
   ロボットを開口部に誘導する。

```
経路点: [..., 壁手前セル, 壁の向こうセル, ...]
                              ↑
          物理的には壁があるが、Nav2ローカルコストマップが
          実際の壁貫通を防ぎ、回復動作が開口部を探す
```

**E2E検証結果**:
- 終了コード: 0（ゴール到達成功）
- AMCL 最終位置: dist = 0.062m（ゴール (-1.25, 3.5) から 0.25m 以内）
- `Failed to make progress` エラー: 数回発生するが回復動作で解消

### LOS チェックを使った場合との比較

| アプローチ | 壁接触 | 実際のゴール到達 |
|---|---|---|
| LOS チェックなし（採用） | `Failed to make progress` 発生あり | **dist = 0.062m（真の成功）** |
| LOS チェックあり + range=30 | エラーなし | dist ≈ 1.2m（偽の成功、y ≈ 2.4 で停止） |

LOS チェックありではロボットが開口部を越えられず経路が y ≈ 2.4 で途切れ、
Nav2 がその終端をゴール到達と誤判定する（偽陽性）。

### 残課題

- `Failed to make progress` エラーはナビゲーション品質の低下を示す
- 回復動作（spin）が壁付近で障害物衝突を検出して失敗する場合がある
- 根本的解決には **波面伝播法（wavefront propagation）** への移行が必要

## 問題3: no_progress カウントによる壁迂回の打ち切り

### 現象

壁を迂回する際、一時的にゴールから遠ざかる動き（横移動）が必要になる。
M9 T-002 で追加した `no_progress_count >= 50` による強制終了が
この迂回を途中で打ち切っていた。

### 回避策: no_progress_count の削除（M9 T-003 バグD）

`no_progress_count` 関連の変数・チェックブロックを削除。
終了条件は以下で担保:

| 終了条件 | 実装 |
|---|---|
| 経路長超過 | `path_length > max_path_length_`（20m） |
| 制御点数上限 | `path_.size() > 300` |
| 重複検出 | 連続2点が同一セルになったら `break` |

## 問題4: スケール不一致による局所解脱出の誤動作

### 現象（M9 T-002 バグA）

脱出ループの `J_min` の初期値として `J_min_pre`（ポテンシャル値 = 数十〜数千）を
設定していたが、J は正規化比率（0〜1）のため、常に `J <= J_min` が真になり
最初のセルが無条件に選ばれていた。

### 回避策

```cpp
// 修正前（バグ）
double J_min = J_min_pre;  // 大きな数値

// 修正後
J_min = std::numeric_limits<double>::infinity();
```

## APF の構造的限界と将来的な解決策

### 現在の APF 実装の問題点

| 問題 | 原因 |
|---|---|
| 狭い開口部を通れない | Euclidean 引力: 開口部が斥力の「山」になる |
| 局所解が不可避 | 引力・斥力の釣り合いが生じやすい |
| 経路の再現性が低い | 脱出がランダムジャンプに依存 |

### 波面伝播法（wavefront propagation）との比較

| 特性 | APF (現状) | 波面伝播 / Dijkstra |
|---|---|---|
| 局所解 | 発生する | 発生しない |
| 狭い開口部 | 通れない | 通れる |
| 計算量 | O(1) / ステップ | O(N log N) |
| 経路品質 | ランダム性あり | 最短・安定 |
| 独自性 | **weighted escape が特徴** | 汎用アルゴリズム |

### 将来的な改善案

1. **ハイブリッド法**: Dijkstra でゴールへの方向を求め、weighted escape でその方向に誘導する
2. **ナビゲーション関数法**: 調和関数を用いた APF 変形でポテンシャルの局所解を排除
3. **膨張コストの APF 反映**: `LETHAL_OBSTACLE` のみでなく `INSCRIBED_INFLATED_OBSTACLE` も
   斥力計算に含め、開口部中心の斥力を低減する
