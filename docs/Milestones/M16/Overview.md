# M16: 壁貫通自動検出 + 自己位置乖離リセット + 地図置換

## 目的

M15で達成した成功率80%をさらに改善するため、壁貫通の自動検出、自己位置乖離時のGazeboリセット、不完全な地図の置換を行う。

## 実施した変更

### 壁貫通自動検出（T-001/T-002）
- `/plan`トピックの経路点と内挿点(0.05m間隔)をstaticマップで壁貫通判定
- CSVに`wall_violations`カラム追加
- field_resolution=0.1で壁貫通なし確認（3ゴール/10ゴール）→100ゴールでは847件検出

### 自己位置乖離検出 + Gazeboリセット
- odomとamcl_poseの乖離(>2.0m)を監視
- 乖離検出時: ゴールキャンセル → Domain 0のGazebo `set_entity_state`サービスでロボットをテレポート → AMCL再初期化
- `gazebo_ros_state`プラグインをwillowgarage.worldに追加
- domain_bridge(humble)はサービス転送非対応のため、Domain 0用の別コンテキスト・エグゼキューターで直接サービス呼び出し

### 地図置換
- willowgarageの地図をpal-robotics/pal_maps版（完全版）に置換
- ワールドファイルのモデルpose=(-20.01, -17.06)に調整（目視確認済み）

## テスト結果

### field_resolution=0.1 × 旧地図（100ゴール）
| 指標 | 値 |
|------|-----|
| 成功 | 62% |
| スタック | 16% |
| タイムアウト | 13% |
| 自己位置乖離 | 9% |
| 壁貫通 | 847件 |
| **壁貫通なしの成功率** | **84%** |

### field_resolution=0.05 × 新地図（41ゴール中断）
| 指標 | 値 |
|------|-----|
| 成功 | 12% |
| スタック | 78% |
| 壁貫通 | 58件 |

### 新地図での問題
- (5.7, 7.6)付近で14回、(5.2, 9.3)付近で13回の連続スタック
- 走行距離<0.1mの即スタックが大半 — 特定の狭所でコントローラーが動き出せない
- field_resolution=0.05でも壁貫通58件（新地図の壁構造の影響）

## 残課題

1. **特定狭所でのスタック**: 新地図の特定地点でロボットが閉じ込められる。プランナーの経路品質改善 or 狭所回避が必要
2. **壁貫通**: 新地図でも発生（58件）。APFの障害物設定ロジックの追加改善が必要
3. **field_resolution=0.1の壁貫通**: 100ゴールで847件。0.1mでは不十分で0.05mが必要だが計算コスト増
4. **スタック時のGazeboリセット**: 現在は自己位置乖離時のみ。スタック検出時にもリセットすべきか
