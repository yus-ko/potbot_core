# M14: T-007 ランダムナビゲーション結果に基づく改善計画

## テスト条件
- マップ: willowgarage
- ゴール数: 100
- ゴール領域: x=[-8, 15], y=[-3.5, 12]
- コントローラー: HybridApfController
- プランナー: potbot_nav::planner::APF (field_resolution=0.1, max_path_length=20.0)

## 結果サマリ
| 結果 | 件数 | 割合 |
|------|------|------|
| 成功 | 1 | 1% |
| スタック | 20 | 20% |
| タイムアウト | 18 | 18% |
| プランナー失敗 | 61 | 61% |

---

## 問題分析と改善計画

### P1: APFプランナーの経路生成失敗（61%）— 最優先

**原因分析:**
- APFプランナーのグリッドサイズが `100x100 grid × 0.1m/cell = 10m×10m` で、それを超えるゴールに経路を生成できない
- 4.4mの近距離でも失敗するケースがあり、ローカルミニマムに陥っている可能性
- `escape_method: "virtual_obstacle_vortex"` による脱出が `max_escape_attempts: 3` で打ち切られている

**改善案:**
1. **グリッドサイズの拡大**: `field_resolution` を下げるか、グリッドサイズ上限を引き上げて広域経路計画を可能にする
2. **A\*ベース経路探索の強化**: `planning_method: "astar"` で使用しているが、APFフィールドとA\*の統合にボトルネックがある可能性。M13の高速化成果を検証
3. **フォールバックプランナー**: APFが失敗した場合にNavfnPlanner等にフォールバックする仕組み
4. **ゴール距離に応じたフィールド解像度の動的調整**: 遠いゴールは粗い解像度で概略経路を計画

### P2: スタック（20%）— 高優先

**原因分析:**
- path_length ≈ 0m のスタック（12件/20件）: プランナー失敗後、リカバリーも失敗して即座にスタック
- path_length > 0 のスタック（8件/20件）: 途中まで走行後に壁際でスタック
- Nav2のリカバリービヘイビア（spin/backup/wait）が効果的に機能していない
- `backup failed` ログが複数確認されており、背面に障害物がある状態でbackupが実行不能

**改善案:**
1. **リカバリー戦略の強化**: costmapクリア + より大きな角度でのspin + 前方への低速走行の組み合わせ
2. **HybridApfControllerの壁回避能力向上**: `k_rep`（斥力係数）や `obstacle_cost_threshold` の調整
3. **RotateToGoalDirection の活用**: 現在コメントアウトされている。ゴール方向へ回転してから走行を開始する戦略
4. **スタック検出後のゴール再設定**: 近傍の到達可能な中間ゴールを自動設定

### P3: タイムアウト（18%）— 中優先

**原因分析:**
- 全タイムアウトが0-6mの近距離で発生
- path_lengthが1-6mあり、ロボットは動いているが目的地に到達できない
- コントローラーのゴール近傍での振動（oscillation）が疑われる
- `goal_tolerance: 0.25m` だが、AMCLの位置推定誤差と合わせるとゴール判定が不安定な可能性

**改善案:**
1. **goal_toleranceの緩和**: 0.25m → 0.5m に拡大してゴール到達判定を緩くする
2. **ゴール近傍での速度制御改善**: lookahead_distanceやv_maxの調整
3. **progress_checkerの調整**: `required_movement_radius: 0.3` → 0.15 に縮小して、微小な振動でもprogressとして検出
4. **Oscillation検出**: DWBのOscillationCriticに相当する機能をHybridApfControllerに追加

### P4: ロボット位置のドリフト — 低優先（テスト基盤側の改善）

**原因分析:**
- 失敗時にロボットが少量移動し、初期位置から離れていく
- テスト終盤はx=14-16m付近に漂流し、ほぼ全ゴールが到達不能

**改善案:**
1. **ナビゲーション失敗時に初期位置へ帰還**: 失敗後に初期位置へのゴールを設定して戻す
2. **ゴール生成のロボット現在位置基準化**: 初期位置ではなく現在位置を基準にゴールを生成（ただし連結成分の再計算が必要）
3. **goal_regionを狭くする**: 初期位置周辺のAPF到達範囲内（10m以内）に限定

## 実施優先順位

| 順位 | マイルストーン | 内容 | 期待効果 |
|------|-------------|------|---------|
| 1 | M15 | APFプランナーの広域経路計画対応（グリッド拡大 or 動的解像度） | 成功率 +30-40% |
| 2 | M16 | コントローラーのゴール到達判定改善 + goal_tolerance調整 | タイムアウト -15% |
| 3 | M17 | リカバリー戦略強化 + スタック脱出機能 | スタック -15% |
| 4 | - | テスト基盤改善（失敗時の帰還 or 位置基準ゴール生成） | テスト精度向上 |

## 即座に適用可能なパラメータ調整（コード変更不要）

```yaml
# waffle_pi.yaml で試すべき調整
planner_server:
  ros__parameters:
    GridBased:
      field_resolution: 0.2      # 0.1 → 0.2 でグリッド範囲を4倍に拡大
      max_path_length: 40.0      # 20.0 → 40.0
      max_escape_attempts: 5     # 3 → 5

controller_server:
  ros__parameters:
    general_goal_checker:
      xy_goal_tolerance: 0.5     # 0.25 → 0.5
    progress_checker:
      required_movement_radius: 0.15  # 0.3 → 0.15
      movement_time_allowance: 20.0   # 30.0 → 20.0（スタック早期検出）
```
